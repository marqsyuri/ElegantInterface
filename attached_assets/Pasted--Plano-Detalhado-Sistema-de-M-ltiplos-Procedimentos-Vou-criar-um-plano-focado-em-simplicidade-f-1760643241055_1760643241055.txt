📋 Plano Detalhado: Sistema de Múltiplos Procedimentos
Vou criar um plano focado em simplicidade, funcionalidade e manutenibilidade.

🎯 Estratégia de Implementação
Arquitetura Escolhida:
Tabela intermediária appointment_procedures (muitos-para-muitos)
Campos calculados em appointments (total_price, total_duration)
UI agrupada por categoria com seleção múltipla
Painel lateral com resumo em tempo real
📐 Plano de Tarefas
FASE 1: Banco de Dados (45-60 min)
1.1 - Criar tabela intermediária

Nova tabela appointment_procedures com:
appointment_id (FK para appointments)
procedure_id (FK para procedures)
order (ordem de execução)
Campos snapshot: procedure_name, price, duration, ppe, materials
Índices para performance
1.2 - Adicionar campos calculados em appointments

total_price (DECIMAL)
total_duration (INTEGER em minutos)
procedure_count (INTEGER)
Manter procedure_id como nullable (deprecado gradualmente)
1.3 - Migração de dados existentes

Script para migrar appointments existentes
Criar registro em appointment_procedures baseado no procedure_id atual
FASE 2: Backend (2-2.5 horas)
2.1 - Atualizar schema Drizzle

Definir relação muitos-para-muitos
Tipos TypeScript para arrays de procedures
2.2 - Funções de Storage

createAppointmentWithProcedures(): criar appointment + múltiplas procedures
getAppointmentWithProcedures(): buscar com join
calculateAppointmentTotals(): helper para cálculos
2.3 - Lógica de Cálculos

Preço total: sum(procedure.price)
Duração total: sum(procedure.duration)
PPE agregado: merge de arrays únicos com contagem
Materials agregados: merge de arrays únicos com contagem
Comissão: calculada sobre total_price
2.4 - Atualizar rotas API

POST /api/appointments: aceitar procedure_ids: number[]
GET /api/appointments/:id: retornar com array de procedures
PUT /api/appointments/:id: permitir editar procedures
FASE 3: Frontend - Booking System (2.5-3 horas)
3.1 - Step 1: Seleção de Procedimentos

Layout: Acordeão por categoria (como tem atualmente)
Seleção: Checkbox em cada card de procedimento
Visual: Card destacado quando selecionado
Painel lateral fixo (mobile: bottom sheet):
📝 Procedimentos Selecionados (2)
✓ Hair Colour Dye - $150 - 90 min
✓ Hair Botox - $120 - 60 min
─────────────────────────────
Total: $270 | 2h 30min
[Continuar →]
Validação: Mínimo 1 procedimento selecionado
3.2 - Step 2: Seleção de Profissional

Filtrar profissionais que podem fazer todos os procedimentos
Mostrar resumo dos procedimentos no topo
3.3 - Step 3: Calendário

Calcular slots baseado em total_duration
Mostrar duração total no card de horário
Ex: "11:00 - 13:30 (2h 30min)"
3.4 - Step 4: Confirmação

Lista completa de procedimentos
Breakdown de preços individuais + total
Duração total
PPE e Materials consolidados
FASE 4: Frontend - Admin (1.5-2 horas)
4.1 - Dashboard de Agendamentos

Card de appointment mostra lista de procedures
Formato compacto: "Hair Dye + 2 more"
Expandir para ver todos
4.2 - Página de Appointments

Coluna com múltiplos badges de procedures
Modal de detalhes mostra tabela completa
Total price e duration destacados
4.3 - Formulário de Novo Agendamento (Admin)

Multi-select de procedures com busca
Preview em tempo real de totais
Mesma lógica do booking público
4.4 - Página de Edição

Permitir adicionar/remover procedures
Recalcular totais automaticamente
FASE 5: Sistema de Notificações (30-45 min)
5.1 - Atualizar appointment_reminders

Trocar procedure_name para procedures_summary
Ex: "Hair Colour Dye, Hair Botox (2 procedimentos)"
5.2 - Atualizar findUpcomingAppointments()

JOIN com appointment_procedures
Concatenar nomes dos procedures
5.3 - Templates de mensagem

Adaptar para mostrar lista de procedures
FASE 6: Relatórios e Financeiro (1 hour)
6.1 - Cálculo de Comissões

Baseado em total_price
Distribuição por procedimento (se necessário)
6.2 - Relatórios

Procedure mais vendido (contar em appointment_procedures)
Combos mais comuns
Receita por procedimento
6.3 - Inventory tracking

Consolidar PPE/Materials de múltiplos procedures
Atualizar estoque baseado na soma

✅ Cálculos no backend: Totais calculados e salvos (não recalculados sempre)
✅ UI progressiva: Mostrar resumo em tempo real
✅ Mobile-first: Bottom sheet para resumo no mobile
